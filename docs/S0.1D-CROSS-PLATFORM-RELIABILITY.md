# S0.1D — Windows / Android multiplayer reliability

## Implementation

OpenRA2 supports experimental mixed-platform lobby sessions. The host must
enable **Cross-platform (experimental)** in the lobby, and both clients must
have compatible simulation versions, map digests and effective game rules.
The test suite validates platform admission separately from deterministic
simulation; a Windows desktop binary or Android APK with actual game data
is still needed for a hardware pass.

### V3 relay recovery

- `MpNet::refresh_tunnel(now)` sends a V3 registration using the existing
  tunnel ID and UDP socket and, when needed, a fresh tunnel RTT ping.
- The Android **lobby foreground** path refreshes the registration before
  issuing the BACK message.
- The in-game **foreground** path also refreshes registration before BACK,
  without resetting simulation frame, session seed, commands or input history.
- Opening a new tunnel session clears old keepalive, ping nonce and RTT state.
  Reserved V3 ID 0 and empty relay addresses are rejected.
- Periodic V3 keepalive (every 5 seconds) remains the safety net.
- On Android foreground in the **Internet room browser**, poll the existing
  control connection, then request a fresh directory; if it failed while
  suspended, reconnect without replaying stale room responses.
- The central lobby's default TCP idle grace is now **120 seconds**, longer
  than the Android lobby's 90-second AWAY allowance (the previous default
  of 60 seconds could delete a suspended host's room). Explicitly configured
  operator timeouts remain honored. This is not indefinite persistence.

### Important limitations

The V3 relay does not use authenticated, immediate endpoint migration. It
blocks a new remote socket that claims a *currently active* V3 ID until the
previous endpoint's timeout (30 seconds by default), to reduce trivial ID
takeovers. Consequently, switching from Wi-Fi to cellular may experience a
temporary interruption, even though the client refreshes its socket on BACK.
Do **not** reduce the timeout or override this safety gate as a workaround.
Fast verified roaming requires a dedicated authenticated rebind design.

A fully lost lockstep connection can still end a game. This slice does not
promise that an arbitrary multiplayer game will continue after a host
disconnects, or that it can recover a timed-out game session.

### Automated verification

- `tests/test_mp.cpp`: V3 foreground refresh sends an immediate registration,
  preserves the current socket and ID, and resets stale state on new session.
- Existing cross-platform admission test checks the host's experimental
  platform setting and rejects clients when disabled.
- Existing Android AWAY/BACK lobby tests cover a simulated background freeze.
- The Go lobby test suite asserts default TCP idle grace exceeds Android AWAY
  and that explicit operator configuration is respected.
- `.github/workflows/online-browser.yml` builds the Linux native C++
  engine and its multiplayer tests.
- `server/internal/tunnel/tunnel_test.go` covers refused takeover from a
  new endpoint while the old mapping is active, and rebind after timeout.

### Real device acceptance (not automated here)

1. Build matching desktop and Android clients from the same commit.
2. Use legitimate owned RA2/YR game files; match rules, art, AI and map data.
3. Host from Windows, enable Cross-platform (experimental), join with Android.
4. Reverse the hosts: Android host, Windows joiner.
5. Verify real gameplay commands and matching frame CRC trails for at least
   3000 frames per direction; collect screenshots/logcat/desktop logs.
6. Pause/foreground the Android client in lobby and match, confirming timely
   BACK handling without a false disconnection.
7. Switch Wi-Fi/cellular during an active match and measure the *actual*
   outage and outcome; do not call it seamless until authenticated roaming
   exists.
8. Repeat simultaneous multiple matches against the same temporary server.
9. Repeat through public Internet/NAT with controlled firewall and bandwidth;
   record loss, RTT and relay throughput before a public VPS rollout.

No VPS deployment or automatic merge into `master` is authorized.
